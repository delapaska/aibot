# AGENTS.md — правила работы ИИ-ассистентов в этом репозитории

Основной источник правил для ИИ-агентов (Claude Code, Copilot и др.), работающих с кодом проекта. Начинай любую задачу с чтения этого файла.

## О проекте

Сервис учёта семейных расходов:

- **Telegram-бот с LLM-агентом** — члены семьи добавляют/смотрят/меняют/удаляют траты обычным текстом («кофе 350», «удали такси»). Каждый пользователь видит только свои траты.
- **Веб-панель главы семьи** — CRUD по тратам всех членов семьи с фильтрами (член семьи, период, категория), без авторизации (по ТЗ), через REST API.

Бэкенд на Go, фронтенд на React + TypeScript, БД PostgreSQL, запуск — один `docker compose`. LLM — любой OpenAI-совместимый API, настройки через env.

## Структура

- `backend/` — Go-модуль `github.com/delapaska/aibot`
  - `cmd/aibot/` — точка входа (сборка зависимостей, graceful shutdown)
  - `internal/domain/` — сущности и бизнес-правила; **не импортирует** ничего из app/adapter/infra
  - `internal/app/port/` — интерфейсы (порты): репозитории, LLM-клиент, часы
  - `internal/app/usecase/` — сценарии приложения; зависят только от портов и домена
  - `internal/infra/` — реализации портов и инфраструктура: `httpapi/`, `telegram/` (long polling), `llm/` (OpenAI-совместимый), `postgres/` (pgx, миграции), `clocksys/`, `config/` (env-конфиг)
- `frontend/` — React + Vite + TypeScript, статика встраивается в Go-бинарь
- `docs/` — `architecture.md`, `security.md`
- `docker-compose.yml`, `Dockerfile`, `Makefile`, `.env.example`

## Команды

- `make build` — собрать бэкенд в `backend/bin/aibot`
- `make test` — все тесты бэкенда
- `make run` — запустить локально (нужен `.env`; БД — `docker compose up -d db`)
- `make vet`, `make fmt` — линт и форматирование
- `make docker-up` / `make docker-down` — поднять/остановить весь стек

## Архитектурные правила

1. Поток зависимостей только внутрь: `adapter → app/usecase → domain`. Домен не знает про БД, HTTP, Telegram и LLM.
2. Юзкейсы зависят от интерфейсов из `app/port`, а не от реализаций. Адаптеры и инфраструктура реализуют порты.
3. Адаптеры тонкие: парсинг входа → вызов юзкейса → формат ответа. Бизнес-логики в адаптерах нет.
4. Внешние зависимости — только после обоснования: предпочитаем stdlib (net/http, slog, pgx как единственный драйвер БД).

## Инварианты безопасности (нарушать нельзя)

1. **Изоляция данных.** `user_id` никогда не приходит от LLM или из недоверенного клиента: в боте — только из Telegram-отправителя, в панели — явный параметр запроса. Репозитории всегда фильтруют выборки/изменения по `user_id` (анти-IDOR).
2. **SQL** — только параметризованные запросы pgx. Конкатенация строк в SQL запрещена.
3. **Валидация на границах.** Все входные данные (REST DTO, аргументы инструментов агента) проверяются: сумма > 0, категория из белого списка, дата не в будущем, лимиты длин строк.
4. **LLM.** Модель не исполняет SQL/команды/код; действия — только через фиксированный набор инструментов с JSON-схемами. Аргументы инструментов валидируются сервером; `user_id` подставляется сервером.
5. **Секреты** — только через env/`.env`; не логировать, не коммитить (`.env` в `.gitignore`).
6. **Логи** — slog, без секретов; PII минимум (telegram id допустим).
7. Сообщения бота длиннее лимита — отклонять; per-user rate limit обязателен.

## Соглашения по коду

- Go: gofmt; ошибки оборачивать через `fmt.Errorf("...: %w", err)`; `context.Context` — первый аргумент.
- Комментарии и идентификаторы в коде — на английском; пользовательские строки (ответы бота, UI панели) — на русском.
- Коммиты — Conventional Commits: `feat(domain): ...`, `fix(api): ...`, `chore: ...`.
- Каждый коммит собирается и проходит `make test`.

## Тестирование

- Юнит-тесты: домен, юзкейсы (фейковые репозитории), агент (фейковый LLM на httptest), HTTP-хендлеры (httptest).
- Интеграционные тесты репозиториев требуют Postgres (`docker compose up -d db`) и пропускаются, если БД недоступна.
- Новая логика — с тестами; багфикс — с тестом, воспроизводящим баг.
- Тестовые дубли — ручные фейки в `internal/app/port/fakes`, а не кодогенерация (Mockery/gomock): фейки — это in-memory реализации контракта (скоупинг, ErrNotFound, сортировка), а не моки с ожиданиями вызовов; портов мало, а зависимости проекта держим минимальными.
- CI (GitHub Actions, `.github/workflows/ci.yml`): vet + gofmt + тесты с `-race` на Postgres из service-контейнера; покрытие публикуется в Step Summary, порог — 70% (`make cover` локально); бейдж покрытия — самодельный SVG на GitHub Pages (ветка `gh-pages`), без внешних сервисов вроде Codecov — доступен из РФ.
