# aibot — ИИ-бот учёта семейных расходов

[![CI](https://github.com/delapaska/aibot/actions/workflows/ci.yml/badge.svg)](https://github.com/delapaska/aibot/actions/workflows/ci.yml)
[![coverage](https://delapaska.github.io/aibot/coverage.svg?v=2)](https://github.com/delapaska/aibot/actions/workflows/ci.yml)

Сервис учёта семейных расходов: член семьи пишет боту в Telegram «кофе 350» — трата сохраняется, бот сам определяет сумму, категорию и дату. Глава семьи смотрит траты всех в веб-панели.

## Что сделано

**Telegram-бот с LLM-агентом** (без команд и кнопок, только обычный текст):

- траты: добавить («кофе 350», «такси 1200 вчера»), показать («покажи траты за неделю», «сколько потратил на еду в этом месяце» — итоги по категориям), изменить и удалить (поиск нужной траты через список);
- долги: записать («Егор взял у меня 500»), список открытых долгов с итогами, закрыть по имени («Егор вернул долг»; если у человека несколько долгов — бот уточняет сумму);
- месячные лимиты по категориям: установка, список с потраченным/остатком, предупреждение сразу при записи траты, превысившей лимит;
- ответы рендерятся локально (подтверждения записей, списки долгов, итоги, лимиты) — без второго запроса к модели: быстрее, дешевле и без «самодельной» арифметики и английских ярлыков в ответах;
- каждый пользователь видит только свои данные: владелец берётся из аутентификации, а не из модели.

**Веб-панель главы семьи** (React + Vite + TS, встраивается в Go-бинарник):

- список трат всех членов семьи с фильтрами (член семьи, период, категория), создание, редактирование, удаление;
- долги: список, создание, отметка о возврате; список членов семьи;
- авторизация не требуется (по ТЗ); опциональный Bearer-токен для API.

**Инфраструктура:**

- LLM через любой OpenAI-совместимый API (по умолчанию OpenRouter): fallback-модели, ретраи с бюджетом времени, защита от обрезанных ответов;
- Telegram long polling; у сообщений есть лимит длины и per-user rate limit;
- Postgres (pgx) с миграциями; всё поднимается одним `docker compose`;
- CI: тесты с реальным Postgres, покрытие — бейдж на GitHub Pages.

## Как запустить

Нужен только Docker.

1. Скопируйте конфиг и заполните его:
   ```sh
   cp .env.example .env
   ```
   Обязательные переменные:

   | Переменная | Зачем |
   |---|---|
   | `TELEGRAM_TOKEN` | токен бота из [@BotFather](https://t.me/BotFather); пусто = работает только веб-панель |
   | `LLM_BASE_URL` | OpenAI-совместимый API, например `https://openrouter.ai/api/v1` |
   | `LLM_API_KEY` | ключ провайдера LLM |
   | `LLM_MODEL` | модель, например `gpt-4o-mini` или `liquid/lfm-2.5-2.6b:free` |
   | `LLM_FALLBACK_MODELS` | резервные модели через запятую (необязательно) |
   | `ALLOWED_TELEGRAM_IDS` | Telegram ID тех, кому разрешён бот (обязательно перед публикацией) |

   Остальные переменные (`POSTGRES_*`, `HTTP_ADDR`, `APP_TZ`, `PANEL_TOKEN`) описаны в `.env.example`.
2. Поднимите стек:
   ```sh
   docker compose up -d --build
   ```
3. Откройте:
   - веб-панель — http://localhost:8080 (авторизация не нужна, по ТЗ);
   - бот — напишите вашему боту в Telegram (первым делом проверьте, что ваш ID есть в `ALLOWED_TELEGRAM_IDS`).

БД доступна только внутри compose-сети (наружу публикуются лишь `127.0.0.1:8080` и `127.0.0.1:5432` для разработки).

### Локальная разработка без Docker

```sh
docker compose up -d db      # только Postgres
make test                    # тесты бэкенда (юнит + интеграционные на Postgres)
make build && make run       # бэкенд (нужен .env)
make panel                   # собрать фронтенд и встроить в Go-бинарник
make test-panel              # тесты фронтенда (vitest)
```

Без `make panel` бинарник работает: по `/` отдаётся заглушка «панель не собрана», API и бот полностью функциональны.

## Архитектура

Чистая архитектура: зависимости направлены строго внутрь.

```
domain (сущности, бизнес-правила; без внешних зависимостей)
  ↑
app/port (интерфейсы: репозитории, LLM-клиент, часы) + app/usecase (сценарии)
  ↑
infra (httpapi, telegram, llm, postgres, clocksys, config)
```

- `backend/internal/domain/` — сущности (Расход, Долг, Лимит) и правила (валидация, копейки);
- `backend/internal/app/port/` — порты; фейки для тестов лежат рядом (`port/fakes`);
- `backend/internal/app/usecase/` — сценарии: сервисы трат/долгов/лимитов и агент, ведущий диалог с моделью через инструменты;
- `backend/internal/infra/` — реализации: REST API (`httpapi`), бот (`telegram`, long polling), LLM-клиент (`llm`), Postgres (`postgres`, pgx + миграции), конфиг из env.

Агент не доверяет модели выбор владельца: каждый вызов инструмента исполняется для аутентифицированного пользователя; чужой id — просто «не найдено». Инструменты агента не принимают `user_id`.

## Безопасность

- `user_id` берётся только из аутентификации (Telegram ID для бота, панель по ТЗ без авторизации);
- SQL — параметризованный (pgx), без склейки строк;
- входные данные валидируются на границах (REST DTO, аргументы инструментов агента);
- секреты — только в `.env` (в git не попадает); доступ к боту — по allow-list `ALLOWED_TELEGRAM_IDS`;
- перед публикацией репозитория смените токен бота (@BotFather) и ключ LLM, если они где-то засветились.

## Тестовое задание

<details>
<summary>Исходный текст задания</summary>

Нужно сделать сервис учёта семейных расходов. Член семьи пишет боту в Telegram «кофе 350», и трата сохраняется: бот сам определяет сумму, категорию и дату.

Сервис состоит из двух частей:

- **Telegram-бот с ИИ-агентом.** Понимает обычный текст: добавляет, показывает, изменяет и удаляет траты. Каждому члену семьи доступны только его траты.
- **Веб-панель для главы семьи.** Показывает траты всех членов семьи и позволяет их редактировать. Авторизация не нужна.

Сущность Трата: `id`, `user_id` (Telegram ID владельца), `amount`, `category` (еда, транспорт, жильё, развлечения, здоровье, покупки, другое), `spent_at`, `comment` (необязательный), `created_at`/`updated_at`.

Требования: бэкенд на Go, фронтенд на любом стеке; приложение запускается со всеми зависимостями через один `docker compose`; доступ к LLM настраивается через конфиг.
</details>
